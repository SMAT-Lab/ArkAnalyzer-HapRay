# Agent 内存分析交付报告（memory-deliverable）

与高负载分析报告（[`analysis-deliverable.md`](analysis-deliverable.md)）区分：本文档规范 **Agent 写给用户的独立内存专题分析报告（Markdown）**，默认路径：

`reports/hapray-analysis-<YYYYMMDD>-<app>-memory-<suffix>.md`（`<PROJECT_ROOT>/reports/` 下）

其中 `<suffix>` 为 `pre` / `post` / `comparison`，规则与 load 报告一致。

---

## 阶段 6 门禁（MUST，写交付报告前）

| 条件 | 动作 |
|------|------|
| 阶段4 memory-analysis 已完成 | 报告主体来自 `hapray_report.db`(memory_*) + `memory_report.xlsx` 真实产物 |
| `memory_records` 表有数据 | 数据源为 `native_hook` 明细或 `native_hook_statistic` 统计（标注精度等级） |
| 存在 `root_cause.md` 且含 memory 信号 | Read 并融合 memory suspect 进 §三 |
| `root_cause.md` 含 `Pending Agent Inference` | **禁止**写阶段 6；先完成 Agent 闭环 |
| 未开 `--memory` 采集 | **禁止**写内存专题报告；提示用户使用 `--memory` 重新采集 |

## 报告类型与产出规则

### 单轮测试（首次分析）

产出 **1 份** pre 报告：
```
reports/hapray-analysis-<YYYYMMDD>-<app>-memory-pre.md
```

### 双轮测试（优化后复测）

产出 **3 份**报告：

| 报告 | 后缀 | 核心内容 |
|------|------|---------|
| 修改前报告 | `pre` | 基线内存数据 + 泄漏分析 + 优化建议 |
| 修改后报告 | `post` | 优化后内存数据 + 泄漏分析（含效果评估）+ 后续建议 |
| 修改前后对比报告 | `comparison` | 逐指标对比 + 逐项优化效果评估 + 综合结论 |

## §根因内容融合规范

**位置**：所有内存根因（CLI `MemoryEvidenceExtractor` + Agent 补充深挖）融合到 **第三章「未释放内存分析」** 和 **第八章「优先级排序」**。

**内容要求（MUST）**：

2. **Agent 补充深挖**：对 CLI 未达源码级的条目（无 `文件:行号` 引用），Agent 借 §0 源码追查后作为**独立根因条目**进入 §八优先级排序。
3. **阶段4 memory-analysis 线索**：本文 §三~§七 的分析结果直接来自阶段4 的 SQL/Excel 查询，不需要重复查询。

**禁止**：
- 仅复述 HTML 摘要而无阶段4 SQL/Excel 证据
- 有 `root_cause.md` memory 信号却未引用
- 伪造 callchainId、地址、内存大小
