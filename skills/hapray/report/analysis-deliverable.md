# Agent 分析交付报告（analysis-deliverable）

与 HapRay 自动报告（`hapray_report.html` / `root_cause.md`）区分：本文档规范 **Agent 写给用户的独立 Markdown**，默认路径：

`reports/hapray-analysis-<YYYYMMDD>-<app>-load-<suffix>.md`（`<PROJECT_ROOT>/reports/` 下）

其中 `<suffix>` 为以下之一：

| 后缀 | 使用场景 | 说明 |
|------|---------|------|
| `pre` | 首次分析（修改前） | 代码优化前的基线报告 |
| `post` | 优化后复测（修改后） | 代码优化后重新采集的第二轮报告 |
| `comparison` | 修改前后对比 | 同时引用 pre 和 post 数据的对比报告 |

**命名示例：**

```
reports/hapray-analysis-20260601-saltplayer-load-pre.md
reports/hapray-analysis-20260601-saltplayer-load-post.md
reports/hapray-analysis-20260601-saltplayer-load-comparison.md
```

## 报告类型与产出规则

### 单轮测试（首次分析）

产出 **1 份** pre 报告：

```
reports/hapray-analysis-<YYYYMMDD>-<app>-load-pre.md
```

### 双轮测试（优化后复测）

产出 **3 份**报告：

| 报告 | 后缀 | 核心内容 |
|------|------|---------|
| 修改前报告 | `pre` | 基线数据 + 根因分析 + 优化建议 |
| 修改后报告 | `post` | 优化后数据 + 根因分析（含优化效果评估）+ 后续优化建议 |
| 修改前后对比报告 | `comparison` | 逐指标对比 + 逐项优化效果评估 + 综合结论 |

**禁止**用 1 份对比报告替代 3 份独立报告。每份报告必须能独立阅读，包含完整上下文。

## 报告结构与模板（MUST）

### 通用规则

1. **中文撰写**，中文章节编号（一、二、三…）
2. 根因按 **P0/P1/P2/P3** 优先级排列，每条包含 **HapRay 证据 + 源码根因 + 修复建议** 三段式
3. 源码引用格式：`文件相对路径:行号`，代码块标注语言类型
4. 优先级标签格式：`[严重] P0` / `[中等] P1` / `[低] P2` / `[建议] P3`
5. 数字使用人类可读格式：指令数用 M/B 单位（如 5.42B），百分比保留 2 位小数
6. 表格中关键数值**加粗**标记

## §空刷根因内容融合规范

**位置**：根因信息融合到 **第三章「根因分析与源码定位」**，不单独成章。

**内容要求（MUST）**：

1. **Read** 磁盘上的 `root_cause.md`（禁止凭记忆缩写）
2. 将 root_cause.md 中的 Top Suspects 按优先级整合到 §三 的各条根因中：
   - root_cause 的 HIGH 嫌疑 → 对应 P0 根因条目
   - root_cause 的 MED 嫌疑 → 对应 P1 根因条目
   - root_cause 的 LOW 嫌疑 → 对应 P2/P3 根因条目
3. 每条根因的「HapRay 证据」部分引用 root_cause 的具体数据（空刷帧数、嫌疑排名、触发链路等）
4. root_cause 中的 Caveats 和补充数据 → 融入「未覆盖项」或在相关根因中注明

**禁止**：

- 仅写 5 行摘要表 + 外链
- 阶段 5 未完成却声称根因已分析
- 内嵌内容与 `root_cause.md` 不一致（若需补充 Agent 解读，写在结论分级，不覆盖根因正文）
- 将 root_cause.md 全文机械复制为独立章节（必须融合到 §三 的三段式结构中）
